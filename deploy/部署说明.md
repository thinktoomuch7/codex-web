# 部署说明

网关和 Codex app-server 是两个 systemd 单元。浏览器只连网关。app-server 只监听本机 Unix socket `/run/codex/app.sock`，不要把它暴露到公网。

网页默认绑定 `127.0.0.1`。从别的电脑访问时，用 SSH 隧道或 Tailscale，不要把端口直接开到公网上。

出站代理用服务器上已经在跑的 mihomo：`https_proxy=http://127.0.0.1:7890`。这个变量写在单元文件里，不写进仓库配置以外的第二套代理。

## 1. 安装运行环境

在服务器上安装 Node.js 22、官方 Codex 的 gnu 包和 bubblewrap，创建系统用户 `codexweb`，并增加约 2GB swap。这一步不要执行 `codex login`。

每次改动服务器后，用 `/usr/local/sbin/ops-log` 记一笔到 `/var/log/ops/operations.log`。不要把订阅地址、令牌或节点密码写进日志。

## 2. 放置程序

把仓库放到 `/opt/codex-web`，在仓库根目录执行 `npm install` 和 `npm run build`。构建结果在 `web/dist`，网关会把它和 API 放在同一个端口上。

配置文件放在 `/etc/codex-web/config.json`，从 `config.example.json` 复制后修改：

- `bindHost` 保持 `127.0.0.1`，除非你已经决定用 Tailscale 地址。
- `projectRoots` 只放允许 Codex 读写的目录，例如 `/srv/projects`。
- `appServerSocket` 使用 `/run/codex/app.sock`。
- `allowedCodexVersions` 填本机 `codex --version` 打出的版本号。版本不在名单里时，网关拒绝启动。
- `dataDir` 使用 `/var/lib/codex-web`。会话正文不在这里，而在 Codex 自己的 `CODEX_HOME`。
- 把 `password` 改成网页登录密码。它和 Codex 账号不是同一个东西。

目录所有者设为 `codexweb`。`/var/lib/codex-web` 和 `/srv/projects` 需要该用户可写。

## 3. 安装单元

```sh
cp deploy/codex-app-server.service /etc/systemd/system/codex-app-server.service
cp deploy/codex-web.service /etc/systemd/system/codex-web.service
systemctl daemon-reload
systemctl enable --now codex-app-server.service
systemctl enable --now codex-web.service
```

先确认 app-server 已经在听 Unix socket，再看网关是否起来。网关单元继承 `https_proxy=http://127.0.0.1:7890`。

## 4. 登录 Codex

程序能启动、网页能打开、未登录状态显示正确之后，才做设备码登录。不要在写代码的阶段登录。

登录完成后，用一个会跑一两分钟的真实任务做断开试验：关掉浏览器后，任务仍应留在服务器上；换一个连接打开同一会话，应能看到已有记录和结果。把试验结果写入 `/var/log/ops/operations.log`。

## 回滚

停掉两个单元即可。保留 `CODEX_HOME` 和 `/var/lib/codex-web/app.db`。中断的 turn 不会自动重放，由人在原会话里继续。
