# Proposal

## Why

当前网页是按另一套习惯收出来的壳，和 Pi Web 的工作区、对话栏都对不上。这次整体重做界面，能对齐的都按 Pi Web 对齐。只使用 Codex 官方已经提供的能力和服务器进程本身能做的事，不再额外加一层目录、功能或交互限制。

## What Changes

- 整个工作区按 Pi Web 重做：侧栏是最近会话和按项目归组的会话，中间是同一栏的对话，文件、Git 和终端按 Pi Web 的页面打开。
- 侧栏可以新建会话、改名、置顶、归档、恢复、分叉、删除，并按标题搜索。短标题保留。列表不按日期分组。分叉是整条会话变成一条新会话。正在执行或等待审批的会话不能删除，这是现有删除行为。
- 选择或添加项目时，可以浏览进程读得到的目录，也可以在进程写得到的地方新建目录。选中的目录交给 Codex 作为工作目录。**BREAKING**：取消「必须落在配置的项目根内」。
- 文件页与 Pi Web 的文件页一样，跟着当前项目、它的 worktree 和这条会话的目录：浏览、预览、上传。Git 在这个目录上列出变更和单文件 diff，并保留暂存、还原、提交、推送和创建 pull request。终端在这个目录打开。
- 新建 worktree 与 Pi Web 相同，检出放在仓库旁边的 `<仓库名>-worktrees/<分支名>`。**BREAKING**：不再放到数据目录下的单独文件夹。仓库根才出现 worktree 切换，这也是 Pi Web 的规则。
- 对话栏与 Pi Web 一样按文档流排列：用户消息、Markdown 正文、可折叠的思考、工具调用、这一轮写出的文件、用时，以及小地图。模型在输入框旁。生成时按钮是停止。长对话先画最近一段，再向上查看。选中文字可以引用进输入框，文件可以拖进当前目录。审批留在产生它的那一轮，三个选择不变。下一句在当前轮结束或失败后发送。
- Codex 官方若已经提供用量、压缩或思考档位，界面就显示对应控件。官方没有的 Pi 专有能力不造假入口：Pi 进程和会话文件、插件、技能、子代理配置、MCP 管理、斜杠命令、旁路对话、运行中插话、按单价计算的花费和缓存提示、浏览器推送，以及在操作者自己的电脑上打开文件管理器。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workspace-ui`：整页改为 Pi Web 的侧栏、对话栏、文件页和终端。
- `codex-gateway`：去掉配置根目录限制；文件、上传、Git 和终端作用在所选目录；worktree 改到仓库旁边；不同会话可以同时执行。

## Impact

- 网页工作区整体替换，网关增加目录、文件、终端和仓库旁 worktree。
- 已有的配置根目录限制、数据目录 worktree、右对齐气泡和收起的检查项会被替换。
- 会话正文仍以 Codex 的会话存储为准。浏览器断开后任务继续执行。浏览器仍不能直接提交任意引擎方法。
