# Design

## Context

见 proposal.md 的 Why。网页仍是 Vite + React，网关仍是唯一持有 `codex app-server` 的进程。会话正文仍读 Codex 的会话存储。现有页面把用户消息放在右侧气泡里，工具收进检查项，项目路径被限制在配置根内，worktree 放在数据目录。

## Goals / Non-Goals

**Goals:**

- 用自写界面换成 Pi Web 的侧栏、文档流对话、文件页、Git 和终端。
- 目录选择、新建目录和 worktree 位置与 Pi Web 相同，不再使用配置根或数据目录这层额外限制。
- 新的浏览器操作进入现有白名单，由网关执行。

**Non-Goals:**

- 不引入 Pi Web 的代码、Next.js 或 Pi 的会话进程。
- 不为 Codex 官方没有的 Pi 专有能力做入口。
- 不改变「浏览器断开后任务继续」和「浏览器不能直接提交任意引擎方法」。

## Decisions

- 界面全部在现有 `web/` 里重写。参照 Pi Web 的布局和交互，不复制它的组件或样式文件。
- 登记目录时，网关用进程权限解析路径：读得到就可以登记，父目录写得到就可以新建。删除 `projectRoots` 拒绝逻辑。文件、上传、Git 和终端的路径必须落在该项目、其 worktree 或该会话已记录的目录内，用来防止路径穿越，不是另一份允许根名单。
- worktree 使用 `git worktree add`，目标为仓库上一级的 `<仓库名>-worktrees/<分支名>`。已有会话继续使用原来记下的工作目录。
- 对话按时间线条目渲染成一栏：用户消息、Markdown、思考、命令和文件变更、写出的文件。正文增量仍只追加片段。模型选择调用现有 `model/list`，在下一次继续会话时传入。
- 终端由网关在会话目录启动一个 shell，输出流回该页面。命令不经过模型。实现选用 PTY。若部署环境缺少 PTY 依赖，终端页报告启动失败，不退回一个假的输出框。
- 实现开始时只读核对当前 Codex 版本是否发出用量、压缩和思考档位。有则接上对应控件，没有则不画按钮。

## Risks / Trade-offs

- [网页密码可以浏览进程读得到的目录] → 这是与 Pi Web 对齐后的能力，页面仍要登录。路径穿越检查只挡住会话目录之外的文件读取。
- [已有 dataDir worktree 和新的仓库旁 worktree 并存] → 旧会话沿用已保存的路径，不迁移检出。
- [整页替换会中断正在看的布局] → 部署时重启网关，进行中的 turn 按现有规则标为中断，不自动重放。

## Migration Plan

1. 先改网关的目录、文件、worktree 和终端，并用测试固定路径规则。
2. 再替换网页布局。
3. 没有正在执行的 turn 时部署并重启。回滚时恢复上一版网关和网页；旧会话路径不删除。
