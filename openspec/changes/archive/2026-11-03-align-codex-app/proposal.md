# Proposal

## Why

现在的网页是按管理后台排的：侧栏放整句提示，命令和审批被拆出对话，文字要等一整段结束才出现，而且全机同时只跑一个任务。操作者要的是官方 Codex 应用那套对话习惯，缺的功能也要补上。官方应用可以让多条会话同时干活，这台服务器上的全局锁要拆掉。

## What Changes

- **BREAKING** 取消「全机同时只跑一个 turn」。不同会话可以同时执行。同一条会话一次仍只有一轮，下一句排队。正在跑的会话不能删除。
- 主区域改成一条向上生长的对话。第一条用户消息是第一句气泡。侧栏用短标题，整句提示留在对话里。命令、文件改动和审批嵌在该回合中。文字按模型吐出的速度出现。回合进行时，输入框变成停止。
- 侧栏是当前项目的会话，按最近活动排列，不按日期分组。登记项目留在侧栏角落。网页密码、项目根目录这些服务器事实不再占住主画面。
- Git 仓库里的新会话默认单独检出一份 worktree，避免两条会话改同一棵树。操作者可以改选「直接改这个目录」，用来在这台机器上部署。不是 Git 仓库的目录没有 worktree，几条会话共用该文件夹。检出目录由网关分配在数据目录下的 worktree 根中，浏览器不能自选路径。该目录不放进被检出的仓库，也不放进其他已登记项目的目录。
- 补上这台服务器做得到的官方应用能力：改名、归档与取消归档、分叉、在会话里查找、选择模型、为这条会话设置沙箱和审批策略、审批里的「这一次允许」和「这一会话都允许」、查看 diff、暂存、还原、提交、推送、创建 pull request。
- 语音、听写、在本机编辑器中打开、桌面快捷键和 Codex Cloud 不做。任务继续留在这台服务器上。
- 浏览器断开不停任务。网关或 app-server 消失时，每条仍在执行的任务标成 `interrupted`，不自动重放。对话正文仍只以 Codex 的会话库为准。网页密码登录不变。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `codex-gateway`: 全局单 turn 改为按会话互斥，并允许多条会话并行。会话工作目录可以是登记项目派生出的 worktree。列表把这些检出归回原项目。审批决定增加会话级允许。官方线程操作和 Git 操作进入白名单，浏览器仍不能提交任意引擎方法。
- `workspace-ui`: 工作区改成官方应用那种对话界面。补上短标题、流式正文、回合内的命令与 diff 与审批、输入框上的停止、并行会话各自的状态，以及模型、权限和 Git 操作。

## Impact

- `gateway/src/runtime.ts` 里按全表查找活动任务并拒绝新 turn 的逻辑要改成只拒绝同一条会话上的第二个 turn。`gateway/src/http.ts` 的浏览器白名单、`gateway/src/codex/unix-engine.ts` 要接上线程、检出和 Git 相关方法。
- SQLite 增加平台记录，记下会话属于哪个项目、用的是 worktree 还是项目目录、检出路径在哪。不新增对话正文表。
- `web/src/App.tsx` 和 `web/src/workspace.css` 从现在的分区页面换成对话布局。现有「第二轮被拒绝」的测试改成：另一条会话可以开始，同一条会话不行。
- 仍由网关拉起并持有一个 `codex app-server`。机器是 2 核、约 3.8 GiB 内存；并行会加重负载，不为并行再起一个 app-server。
- 不改网页登录、监听端口、对外地址，也不把 Codex 放回 80 端口。
